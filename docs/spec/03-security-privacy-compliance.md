# 医疗健康协同体平台安全、隐私与合规边界

## 1. 安全目标

- 防止患者和家属越权访问。
- 防止医院跨租户读取。
- 防止政府与药企接触患者级临床正文。
- 防止授权撤销后缓存或接口继续放行。
- 保证计划、授权和审核变更有审计证据。
- 避免在日志、截图和测试夹具中出现真实个人信息。

## 2. 数据分类

| 级别 | 示例 | 演示处理 |
|---|---|---|
| 公开 | 项目介绍、公开来源链接 | 可直接展示 |
| 内部 | 模块配置、接口文档 | 仅开发环境 |
| 敏感个人信息 | 姓名、手机号、病历号、诊疗计划 | 合成数据，应用层加密设计 |
| 高敏健康数据 | 诊断、用药、观察、家属授权 | 仅授权角色可见 |
| 聚合监管数据 | 区域计划数、完成率、提醒数 | 最小人数抑制 |

## 3. 控制措施

认证：

- 密码使用 `scrypt` 加盐哈希。
- 访问令牌短期有效，刷新令牌独立类型。
- Web 使用 HttpOnly Cookie 和 CSRF 双提交令牌。
- 移动端使用 Bearer Token，Android 会话写入 EncryptedSharedPreferences。
- 生产环境必须替换开发密钥并启用 HTTPS；医生和管理员应启用 TOTP 或医院 SSO。

授权：

- RBAC 决定角色能力，ABAC 决定组织、患者和授权范围。
- 家属每次读取都检查授权状态、有效期和字段范围。
- 政府仅能访问 `aggregate` 资源。
- 药企仅能访问本企业和满足发布阈值的聚合资源。

审计：

- 记录主体、角色、动作、资源类型、资源 ID、患者伪标识、组织、目的、请求 ID 和时间。
- 审计记录只追加，不通过普通业务接口修改或删除。
- 敏感读取、导出、授权撤销、计划创建、任务完成和审核决策均记录。

## 4. 最小聚合规则

政府：

- 活跃计划少于 10 的区域，计数、百分比和提醒数全部抑制。
- 如发布总数可反推出小单元，执行互补抑制。

药企：

- 区域、药品、月份分组至少覆盖 3 家机构。
- 至少包含 50 个患者月。
- 不返回患者 ID、医院 ID、医生 ID、诊疗正文或可逆伪标识。

## 5. 合规边界

当前实现不等同于完成以下生产合规工作：

- 网络安全等级保护定级、备案、测评和整改。
- 个人信息保护影响评估和单独同意流程。
- 医疗机构电子病历、互联网诊疗或互联网医院准入。
- 医保信息平台、医保结算或药品采购对接。
- 药品追溯码全链路验证、处方流转和药品配送资质。
- 真实数据出境、委托处理、共同处理或第三方供应商评估。

真实试点前至少需要：

1. 明确数据处理者和个人信息处理者角色。
2. 完成数据分类分级、最小必要和保存期限评审。
3. 由医院和临床专家审核治疗模板及患者可见内容。
4. 建立数据泄露响应、账号停用和应急联络机制。
5. 对接口、移动端和运维环境完成安全测试及合规评估。

## 6. 已知风险

- 微信小程序无法阻止系统截图，只能缩短会话和减少敏感信息展示。
- SQLite 本地演示不具备生产并发、备份和高可用保证。
- 当前演示数据使用固定密码，仅适用于本机隔离环境。
- 官方公开数据可能变更、下架或限制自动化获取，必须保留来源与版本证据。
