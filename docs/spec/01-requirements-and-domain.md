# 医疗健康协同体平台 需求与领域规格

## 1. 产品定位

医疗健康协同体平台是面向教学、开源工程协作和后续试点的治疗方案进度协同 平台。它把医生签署的治疗计划、患者和家属的自护任务、医院内部协同、政府脱敏指标以及药企区域供应反馈组织成一条可追踪路径。

首版使用合成病例和官方公开数据快照，不连接真实患者档案。系统不提供诊断、治疗推荐、电子处方、医保结算、药品交易或真实行政处置。

## 2. 目标与非目标

目标：

- 医生能够从已发布模板创建带版本的治疗计划。
- 患者能够确认计划、查看任务和用药安排，并完成自护任务。
- 家属只能在患者授权范围内查看和代办任务。
- 医院只能查看本院数据，并管理人员、模板和运营指标。
- 政府只能查看脱敏区域聚合指标及平台内审核案件。
- 药企只能维护自身目录、查看达到发布阈值的区域需求并提交产能反馈。
- Web、Android 和微信小程序能够连接同一套 API。
- 官方公开数据能够版本化导入、校验和审计。

非目标：

- 不替代 HIS、EMR、医保平台或政务系统。
- 不建立完整电子病历或完整 FHIR 服务器。
- 不生成诊疗建议。
- 不在首版完成处方流转、药品交易、物流调度或医院生产部署。
- 不承诺 `npm`、GitHub 或官方数据源长期无变化。

## 3. 角色与权限

| 领域角色 | 系统角色 | 默认范围 | 禁止事项 |
|---|---|---|---|
| 患者 | `PATIENT` | 本人档案、计划、任务、授权 | 修改医生计划 |
| 家属 | `CAREGIVER` | 有效授权中的字段和操作 | 查看未授权字段 |
| 医生 | `DOCTOR` | 本人负责且属于当前医院的计划 | 跨院访问 |
| 医院管理员 | `HOSPITAL_ADMIN` | 本院成员、计划和提醒 | 查看其他医院 |
| 政府监管者 | `REGULATOR` | 脱敏区域指标和审核案件 | 查看个人病历 |
| 药企用户 | `PHARMA` | 本企业目录、聚合需求和产能反馈 | 获取患者或医院明细 |
| 系统管理员 | `SYSTEM_ADMIN` | 官方数据快照、运维元数据 | 浏览临床正文 |

家属授权至少包含 `tasks:read`、`tasks:complete`、`medications:read`、`appointments:read`、`observations:read` 和 `observations:write` 中的明确子集，并具有有效期。授权撤销或过期后，后续请求必须被拒绝。

## 4. 核心领域对象

- 组织：医院、社区机构、监管机构、药企和系统运营机构。
- 患者档案：与登录账号分离，包含合成病历号和地区编码。
- 照护授权：患者与家属之间的时间有限、范围有限的访问许可。
- 治疗模板：包含阶段、任务、观察项、用药计划、预约和阈值提醒定义。
- 治疗计划：模板的实例，发布后通过新版本修订，不原地覆盖历史。
- 协同任务：自护、观察、预约或机构任务。逾期由截止时间计算，不保存独立逾期状态。
- 用药安排：计划中的药物、剂量文本和频次，不是处方。
- 观察记录：血压、伤口、症状或其他模板定义指标。
- 提醒：任务逾期、漏服或阈值异常产生的平台内工作项。
- 官方数据快照：来源、版本、发布日期、生效日期、校验值、审核人和内容摘要。
- 需求信号：达到最小聚合阈值的区域药品月度需求。
- 产能反馈：药企对某个药品、区域和月份的供应数量声明。

## 5. 状态机

治疗计划：

```text
DRAFT -> PENDING_PATIENT_CONFIRMATION -> ACTIVE
ACTIVE -> PAUSED -> ACTIVE
ACTIVE -> COMPLETED
ACTIVE -> CANCELLED
```

任务：

```text
PENDING -> IN_PROGRESS -> COMPLETED
PENDING -> SKIPPED
```

提醒：

```text
OPEN -> ACKNOWLEDGED -> RESOLVED
OPEN -> DISMISSED
```

审核案件：

```text
PENDING -> APPROVED
PENDING -> REJECTED
```

## 6. 主要业务规则

1. 医生只能从 `PUBLISHED` 模板创建计划，且患者必须已经在当前医院存在归属关系。
2. 计划版本发布后不可直接修改；任何方案变更生成新记录并保留旧版本。
3. 家属完成自护任务不会改变临床方案、药物剂量或医生签署内容。
4. 逾期、漏服和阈值只产生提醒，不自动改变治疗计划。
5. 政府区域行若活跃计划少于 10，应整体抑制计数、百分比和提醒数。
6. 药企需求信号只有在区域、药品、月份分组同时覆盖至少 3 家机构和 50 个患者月时发布。
7. 官方数据匹配状态为 `VERIFIED`、`UNVERIFIED` 或 `STALE`；医保标签仅为信息展示。
8. 所有临床相关写操作、授权变更、导出和审核决策必须产生审计事件。

## 7. 验收标准

- 使用演示账号完成患者、家属、医生、医院、政府和药企六条 Web 主流程。
- 医生创建计划后，患者/家属端可查看任务并完成同步。
- 家属授权撤销后无法继续读取患者任务。
- 跨机构、越权角色和药企患者级查询都被拒绝。
- 政府聚合结果不含患者标识，并执行最小人数抑制。
- 官方数据快照导入重复校验值时返回冲突。
- Android debug APK 可构建，离线缓存和本地提醒代码路径存在。
- 微信小程序通过 JavaScript 语法和纯逻辑测试；无 AppID 时明确展示沙箱边界。
- 文档、OpenAPI、数据库迁移和容器配置可被另一名开发者复现。
